# Patch: FaceTheory v5.0.0 adoption + Dependabot consolidation wave

- **Impact:** Patch
- **Surface:** Dependency resolution, build toolchain, CI workflow action pins, CLI registry dependency ranges, `examples/facetheory-svelte` integration suite
- **User-facing change:** No component public API, prop, event, export, or theme-token surface changes. `greater` CLI consumers see refreshed (semver-compatible) dependency ranges in the regenerated `registry/index.json` (e.g. `svelte ^5.57.1`, `@tanstack/svelte-virtual ^3.13.39`).
- **Accessibility fix:** `ArtistProfile.Stats` now derives its `aria-label` from the formatted stat value (`1.2K Followers`) instead of the raw number (`1200 Followers`), so the accessible name matches the visible label and satisfies WCAG 2.5.3 Label in Name. This resolves a `label-content-name-mismatch` serious violation newly surfaced by the `axe-core` 4.13.0 → 4.14.0 bump (via `@axe-core/playwright`); the `registry/index.json` checksum for `Stats.svelte` is regenerated accordingly. No prop, event, or export surface changes.
- **Security:** Remediation of all Dependabot-alerted packages in `pnpm-lock.yaml` (devalue, dompurify, undici, brace-expansion, ip-address, js-yaml, fast-uri, browserslist, baseline-browser-mapping, postcss-selector-parser, basic-ftp, @fastify/busboy, @graphql-tools/executor-legacy-ws) plus newly surfaced advisories (shell-quote ≥1.11.0, source-map-js ≥1.2.2, @graphql-tools/utils ≥12.0.1, fflate ≥0.8.3). `pnpm audit` reports zero non-ignored vulnerabilities; the single ignored advisory (GHSA-vfj7-8cjw-p6xm, `braces` via `@graphql-codegen/cli > micromatch`) has no patched release upstream and is dev-tooling-only.
- **Framework alignment:** `@theory-cloud/facetheory` pinned to the v5.0.0 release tarball (sha256 `109fa88bbd40324cb65df9307860d12a67f6e1454e3742c03f872b0b23275d4e` verified against the upstream `SHA256SUMS.txt`; SRI recorded in `greaterVerifiedTarballs` and the lockfile). `pnpm test:facetheory` green against v5.0.0.
- **Toolchain notes (internal, not published surface):** SvelteKit 3 migration for `apps/docs`, `apps/playground`, and the CLI e2e fixture (config moved into the `sveltekit(...)` Vite plugin; `$app/stores` → `$app/state`; `$app/paths` `base` → `resolve`/`asset`; tsconfigs extend `$app/tsconfig`; `vite-plugin-pwa` pointed at the kit client output dir). `@sveltejs/package` 3 requires explicit `svelte-package --input src`. TypeScript stays on ^6.0.2 (typescript-eslint and SvelteKit 3 peers do not support TS 7 yet) and `@graphql-codegen/typescript(-operations)` stay pinned `<6.0.0` (upstream double-emission bug dotansimha/graphql-code-generator#10782 still reproduces on 6.1.10; the generator-replay gate enforces the pin).

Closes #1092.
